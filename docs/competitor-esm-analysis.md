# Анализ референсной системы: Eurohydroservice ESM (панель менеджера)

Источник: видео заказчика, 4:22, `manager.esm.parts` (разработчик — Киберэкс, тот же кейс, что в PDF).
Показана **панель менеджера поставщика**, а не личный кабинет клиента. Звука нет; анализ по 84 уникальным кадрам.

## 3. Модель данных — ключевое открытие

Система двухуровневая, чего нет ни в ТЗ, ни в нашем `entities/types.ts`:

```
Каталог (компоненты)          Рукав в сборе (артикул / BOM)        Изделие (серийная единица)
├─ Рукав  ─────────────────►  Номер ЕГС: 62189                     Номер ESM: A71156
├─ Фитинг (2 шт) ──────────►  Тип: симметричный                    Рукав в сборе: 62189 (ЕГС)
├─ Муфта (2 шт) ───────────►  Угол поворота, Длина (мм)            Контрагент, Филиал контрагента
├─ Защита, Уплотнение,        Тех. документация (PDF)              Филиал ЕГС, Кто изготовил
│  Прижимная плита,           Совместимые модели (по OEM)          Гаражный номер техники
│  Скоба фланцевая,           История рукава (аудит)               Дата отгрузки, Дата установки
│  Болт, Адаптер              Кол-во изделий                       Срок гарантии (дней)
                                                                   Пробег: Километры | Моточасы
                                                                   Статус, Номер заказа, Гарантия до
```

- **Рукав в сборе** — спецификация (что из чего собрано). Один артикул → N изделий.
- **Изделие** — конкретная единица с серийным номером ESM, установленная у клиента.
- **OEM-номер** — связка «Производитель + Марка техники + OEM» → ищет изделия; на артикуле показывается список «Совместимые модели (по OEM)».

## 4. Карточка изделия (A14015)

- **Жизненный цикл** — горизонтальная Gantt-шкала с фазами и длительностями:
  `Рабочий 180д` → `Середина срока годности 90д` → `Требуется замена 90д` → `Не на гарантии`; подпись «Возраст изделия 449 дней»; ось дат под шкалой.
- Блок «Детали»: описание, контрагент, филиал ЕГС, кто изготовил, артикул ЕГС, гаражный номер, дата отгрузки, дата установки, срок гарантии, моточасы/километры, статус.
- Блок «Замены изделия» (таблица: Замена, Дата, Моточасы/Километры, Причина) — первая строка «Выпуск изделия».
- Блок «История рукава» — лента аудита («Иванов создал изделие A14015», дата/время).
- Кнопки: «Изменить изделие», «Создать замену (перевыпустить)».

## 5. Форма «Создать изделие» (модал)

Филиал ЕГС · Кто изготовил · Филиал контрагента · Гаражный номер техники (select) · Описание · Рукав в сборе (поиск + «Выбрать») · Дата отгрузки · Дата установки · Срок гарантии (дней) с быстрыми кнопками **90 / 180 / 270 / 360** · Пробег техники с переключателем **Километры | Моточасы** · **Количество для создания** (пакетное создание N изделий из одного артикула) · кнопки Создать / Очистить.

## 6. Таблицы — общие паттерны

- Вкладки **Активные / Архив (удалённые)** на каждом реестре — мягкое удаление везде.
- Раскрывающиеся строки (`+`) — состав РВД прямо в списке изделий.
- Чекбоксы + «Действия (0 из 170106)» — массовые операции.
- «Фильтры», «Добавить колонки» (выбор колонок), «Добавить изделие».
- Пагинация: `1 2 3 4 5 … 17011 >`, «10 / страница», поле «На страницу» (прыжок).
- Сортировка по любой колонке, «Показано с 1 до 10 из N».
- Статус — цветной pill («Эксплуатация»); даты гарантии серым.

## 7. Журнал замен

Колонки: Замена (id), Дата замены, ESM, Заказ, Гаражный номер, Филиал, Кто заменил, Контрагент, Пробег (ч), **Причина**.
Причины — справочник: `Гарантийная замена`, `Капитальный ремонт`, `По требованию заказчика`.

## 8. Служебные разделы

- **Компания → Пользователи**: вкладки Менеджеры | Контрагенты; ФИО, Email, Роль, Последняя активность. Роли: Администратор, Руководитель компании, Ведущий менеджер, Менеджер, Ведущий сервисный специалист.
- **История**: глобальная лента аудита по всем сущностям с поиском.
- **Штрих-коды**: генератор — выбрать тип, загрузить файл, сгенерировать (маркировка рукавов).
- **Обновления**: changelog внутри системы (последний — 27.10.2025: история OEM, архивирование групп, ошибки валидации, раскрытие состава РВД, срок авторизации, история по товарам каталога, последняя активность, просмотр документов).
- **Заказы**: ID, Филиал, Контрагент, … (в видео пусто).

## 9. Что это меняет для нас

### Модель данных (срочно)

1. Добавить `HoseAssembly` (Рукав в сборе): `egsNumber`, `type`, `length`, `angle`, `hoseCatalogId`, `fittings[2]`, `couplings[2]`, `extra[]`, `docs[]`, `compatibleOem[]`.
2. `Product` получает `assemblyId` (→ ЕГС) и `esmNumber`; `oemNumber` уходит на уровень assembly/OEM-справочника.
3. `Replacement.reason` → enum из 3 значений; `mileage` с единицей `km | h`.
4. Каталог компонентов — 9 типов; для клиентского ЛК достаточно read-only.

Это почти наверняка структура и в 1С заказчика («история жизненного цикла изделия» = Gantt-фазы). Вопрос разработчику 1С: **есть ли у вас разделение Рукав в сборе / Изделие и как они называются в конфигурации?**

### UI-паттерны, которые стоит взять

- Gantt жизненного цикла в карточке изделия (главная «фишка»).
- Быстрые кнопки срока гарантии 90/180/270/360.
- Переключатель Километры | Моточасы.
- Пакетное создание изделий.
- Архив-вкладка вместо удаления.
- Раскрывающийся состав РВД в строке таблицы.
- Выбор колонок + серверная пагинация с прыжком на страницу.
- Лента аудита на карточке и глобальная.

### Чего в референсе нет, а в ТЗ есть (наше преимущество)

- KPI-дашборд с дельтами и цветовой индикацией (в панели менеджера отсутствует).
- Иерархия Компания → Филиал → Техника → Узел → РВД как отдельный раздел «Моя техника».
- Уведомления 30/14/7 дней.
- Экспорт Excel/PDF из любого реестра.
- Сравнение нескольких моделей техники.

### Чего нет ни там, ни в ТЗ — предложить заказчику

- Фото изделия/места установки (в ТЗ упомянуто, в референсе не видно).
- Мобильный сканер штрих-кода → карточка изделия (штрих-коды генерируются, но сканирования в UI нет).
