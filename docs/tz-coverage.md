# РВД Кабинет — покрытие ТЗ

Пункт за пунктом: что из технического задания сделано, где это в кабинете и что ждёт ответа. Номера вопросов — из [PLAN-STATUS.md](PLAN-STATUS.md), «Открытые вопросы». Состояние на 2026-10-07, версия 0.9.0.

**Готово** — работает на API с данными из 1С. **Готово, ждёт** — сделано с нашей стороны, включится или уточнится после ответа. **Нет в 1С** — экран готов, но в 1С этих данных нет: кабинет показывает прочерк.

## 7. Результат

Путь «какие РВД → на какой технике → где → в каком состоянии → когда менять → что стояло раньше → заявка на новое» проходит целиком: реестр или карточка техники → карточка изделия (срок службы, история, замены, заявки) → «Создать заявку на замену» или «Заказать такой же». Сведения о последнем ремонте и гарантийном статусе по каждой машине — на карточке техники и в отчёте «Статистика по технике».

## Ограничения версии 1.0.0-rc.3

- **Ждут разработчика 1С:** справочник причин замены и признак гарантии в OData (вопрос 27), кто выполнил замену (22), почта техподдержки для писем о расхождениях данных (24); техническая документация.
- **Ждут заказчика:** проверка раздела поставщика и приёмка (Д33–Д35), видеоинструкция (Д39), отключение тестовой учётки «ВГИЗ, тест» в день запуска.
- **Данные 1С:** каталожный № заполнен примерно у 14 % изделий, дата установки — редко (срок считается от отгрузки).
