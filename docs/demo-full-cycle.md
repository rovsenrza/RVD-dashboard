# Демо полного цикла заявки (Веха 4, Д20)

Как показать путь заявки «кабинет → 1С → обратно к клиенту», пока у разработчика 1С нет сервиса заявок (вопрос 2). Вместо 1С отвечает заглушка с тем же контрактом ([docs/1c/request-api.md](1c/request-api.md)); всё остальное — настоящее: вход, кэш из 1С, очередь отправки, синхронизация статусов, уведомления. Автоматически тот же путь проверяет `apps/api/src/requests/cycle.test.ts`.

## Запуск

1. Postgres: `docker compose up -d db`, кэш из 1С: `npm run sync -w @rvd/api`.
2. Заглушка 1С (порт 3101): `npm run fake-1c -w @rvd/api`.
3. API, направленный на заглушку (в `.env` или в командной строке):
   ```sh
   ONEC_ORDERS_URL=http://localhost:3101/hs/rvd/v1/requests \
   ONEC_ORDER_STATES_URL=http://localhost:3101/odata \
   SYNC_INTERVAL_MS=60000 npm run dev -w @rvd/api
   ```
4. Веб в живом режиме: `VITE_LIVE_API=true npm run dev`, войти пользователем компании (`npm run user:add -w @rvd/api …`).

## Сценарий

1. **Заявка.** «Мои изделия» → изделие → «Создать заявку на замену» (можно приложить фото). В «Заявках» она сразу видна: «Отправляется в 1С».
2. **1С приняла.** Через несколько секунд очередь отправит её; у заявки появляется номер «СВЦБ-002201», статус «Новая». В «Журнале» администратора — запись о заявке.
3. **Менеджер взял в работу** (в 1С; здесь — рукой менеджера заглушки):
   ```sh
   curl -X POST localhost:3101/manager/orders/СВЦБ-002201 \
     -H 'content-type: application/json' -d '{"status":"ВРаботе"}'
   ```
   Администратор нажимает обновление у строки «Данные 1С на …» внизу боковой панели (или ждёт минуту) — статус «В работе».
4. **Выполнено и отгружено:**
   ```sh
   curl -X POST localhost:3101/manager/orders/СВЦБ-002201 \
     -H 'content-type: application/json' -d '{"status":"Выполнен","shipment":"Отгружен"}'
   ```
   После обновления — статус «Выполнена», отгрузка «Отгружено», в колокольчике — «Заявка СВЦБ-002201 · Выполнена в 1С».
5. **1С недоступна** (по желанию): остановить заглушку и создать ещё одну заявку — она ждёт в очереди с пометкой «Нет связи с 1С — отправим автоматически» и уходит сама, когда заглушка снова запущена.

## Что изменится с настоящим сервисом 1С

Только адреса: `ONEC_ORDERS_URL` — на сервис 1С, его пользователь — в `ONEC_ORDERS_USER`/`ONEC_ORDERS_PASSWORD`, а `ONEC_ORDER_STATES_URL` убрать — статусы будут читаться из той же базы 1С по OData. Открыто у разработчика 1С: как в 1С выглядят новая и отклонённая заявка, пользователь сервиса, файлы заявки (вопрос 2).
