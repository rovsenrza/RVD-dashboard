## Неделя 2 — Auth, multi-tenant, дизайн-система

- [x] Д6 Auth (JWT + refresh), users/roles/scopes, страница входа — **в живом режиме вход настоящий**: компании (= клиент 1С) и пользователи в Postgres, пароли scrypt, access-JWT на 15 минут, refresh в httpOnly-cookie с ротацией, выход, `/me`; сессия переживает перезагрузку, две вкладки или перезагрузка во время обновления токена не выкидывают из кабинета; без `JWT_SECRET` сервер не стартует (кроме `AUTH_DISABLED=true` локально). **Пользователей ведёт администратор компании** на экране «Пользователи»: добавить, изменить, отключить доступ (сессии гаснут сразу), сбросить пароль; себе роль и доступ не меняет. Почты пока нет (вопрос 7), поэтому новый или сброшенный пароль показывается администратору один раз — при первом входе человек обязан придумать свой, до этого сервер не отдаёт данных. «Сменить пароль» — в меню пользователя. Первого администратора компании заводит `npm run user:add -w @rvd/api`. Филиалы пользователя (scopes) — когда в 1С появится деление клиента на филиалы
