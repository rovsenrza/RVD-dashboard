# Заявки кабинета → 1С: предложение по API

Статус: **предложение отправлено разработчику 1С 2026-10-03; схему он принял, реализацию начинает 2026-10-05.** Мы подстроимся под его структуру, если она удобнее. Ответы по пунктам — в разделе 3.

## Откуда это

Разработчик 1С (2026-10-03): у `odata.user` только чтение сырых данных без бизнес-логики; предложил вместо этого функции API — «ПолучитьИзделияПоКлиенту (клиент, дата); СоздатьЗаявку (СтруктураЗаявки) и т. д.». Заявку создаёт сам клиент, менеджер в 1С её проверяет, при необходимости корректирует и утверждает в работу. Заказчик просил: «технически реализуйте, если что-то нужно от меня — я открыт к предложениям».

## Схема

- **Чтение** — OData, как сейчас. Это уже работает: 4 039 изделий, 656 единиц техники, полная синхронизация в кэш около 6 с. Функции чтения от 1С пригодятся позже, для инкрементальной синхронизации (Д26): «что изменилось у клиента с такой-то даты».
- **Запись** — HTTP-сервис 1С (пишет разработчик 1С). Кабинет вызывает его со своего сервера (BFF), не из браузера клиента.

## 1. Создать заявку

`POST {база}/hs/rvd/v1/requests`

- Авторизация — Basic, отдельный пользователь 1С с правом только на этот сервис. Логин и пароль передать отдельно, не в чат.
- Заголовок `Idempotency-Key: <id заявки в кабинете>`. Если связь оборвалась и кабинет отправил ту же заявку ещё раз, дубль не создаётся: 1С возвращает уже созданную.

Тело:

```json
{
  "cabinetId": "req-8f3c2a",
  "client": "cecbd23c-234a-11f1-9bce-98f2b3ef9ffc",
  "kind": "replace",
  "comment": "Срочно, простой техники",
  "author": { "name": "Иванов Иван", "email": "ivanov@example.ru" },
  "lines": [
    {
      "product": "0f9e…",
      "catalogNumber": "3a7b…",
      "catalogNumberText": null,
      "equipment": "b41c…",
      "quantity": 1,
      "comment": null
    }
  ],
  "files": [{ "name": "позиции.xlsx", "url": "https://<кабинет>/api/files/…?sig=…", "size": 18234 }]
}
```

| Поле                        | В 1С                  | Правило                                                                                                                    |
| --------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `client`                    | `Клиент_Key`          | компания кабинета привязана к одному клиенту 1С; `Филиал_Key` 1С берёт из карточки клиента                                 |
| `kind`                      | хранит 1С             | `replace` — Замена, `manufacture` — Изготовление, `repair` — Ремонт                                                        |
| `lines[].product`           | `Изделие_Key` строки  | только у «Замены»: изделие клиента, которое меняем (списанное тоже можно — «сделайте такое же»)                            |
| `lines[].catalogNumber`     | `КаталожныйНомер_Key` | номер из справочника; у «Замены» — номер изделия                                                                           |
| `lines[].catalogNumberText` | хранит 1С             | номер текстом, если в справочнике его нет: менеджер выясняет, что за изделие                                               |
| `lines[].equipment`         | `Техника_Key` строки  | у «Замены» — техника изделия; у остальных — одна на заявку или пусто                                                       |
| `lines[].quantity`          | количество            | 1–99; у «Замены» всегда 1                                                                                                  |
| `files`                     | —                     | временные ссылки на файлы в кабинете; у «Изготовления» и «Ремонта» строк может не быть, если позиции — в приложенном Excel |
| `author`                    | —                     | кто из сотрудников клиента создал заявку: менеджеру для связи                                                              |

Ограничения кабинета — до 10 строк в заявке. Те же правила кабинет проверяет до отправки: в 1С не уйдёт «Замена» с номером, набранным вручную, или заявка без строк и без Excel.

Ответ `201 Created`:

```json
{ "ref": "78986abe-3953-11f1-915d-98f2b3ef9ffc", "number": "СВЦБ-002158", "status": "Черновик" }
```

- Повтор с тем же `Idempotency-Key` → `200` с тем же телом.
- Ошибка данных → `422` и `{ "error": "Изделие 48703 не принадлежит клиенту" }`. Текст кабинет покажет клиенту как есть.
- Таймаут или `5xx` → кабинет повторяет отправку по очереди (Д17). Клиент видит «Отправляется в 1С», заявка не теряется.

В 1С по заявке создаётся «Заказ клиента», помеченный как заказ из кабинета (см. раздел 3), в статусе, который менеджер разбирает: «Черновик» или новый «На согласовании». Менеджер проверяет, при необходимости корректирует и переводит «В работу».

## 2. Статусы обратно в кабинет

- **Вариант А — без доработок 1С.** Кабинет раз в несколько минут читает по OData `Document_ЗаказыКлиента` с источником «из кабинета» по своему клиенту: `СтатусЗаказа`, `Отгрузка` и строки. Если менеджер изменил состав, клиент увидит итоговый, а изменение статуса придёт клиенту уведомлением.
- **Вариант Б.** `GET {база}/hs/rvd/v1/requests?client=…&changedSince=…` — то же, но только изменённые заявки.

## 3. Что нужно от 1С

1. Сервис `POST …/requests` по структуре выше (или ваша структура).
2. Реквизит «Тип заявки» в «Заказе клиента» и поле строки для номера текстом. _Ответ 2026-10-03: без комментариев — 1С принимает структуру с текстовыми полями и разбирает её у себя; у нас это уже отдельные поля `kind` и `lines[].catalogNumberText`. Отладка — на копии базы, рабочую кабинет только читает._
3. В каком статусе создавать заявку из кабинета и как 1С помечает отказ: статуса «Отклонён» в данных нет. _Ответ 2026-10-03 (как пометить заказ из кабинета): `СозданВРВД` значит «создан в базе РВД, а не в УТ», для этого не годится — разработчик предлагает перечисление-источник «РВД / внешний / УТ» вместо флага или отдельный признак «внешняя / внутренняя». Мы за перечисление, значение — «Личный кабинет». Статус новой заявки и отказ — ждём ответа._
4. Пользователь для сервиса.
5. Файлы: хватит ссылки в комментарии заказа или класть их в 1С (БСП) — тогда 1С скачивает по ссылке.

## 4. Что делает кабинет

- Клиент отмечает изделия в «Моих изделиях» → «Заявка на замену», либо создаёт заявку на «Изготовление» или «Ремонт» в форме по типу. Сделано, пока на демо-данных.
- BFF принимает заявку и проверяет её теми же правилами, что и форма (`requestProblem` в `@rvd/contracts`). Затем хранит её, ставит в очередь и отправляет в 1С с повторами. Номер СВЦБ и статус возвращаются в кабинет (Д17–Д18), клиенту — уведомление.
